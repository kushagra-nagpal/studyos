# Design principles

1. **Make the next action obvious.** End with a concrete step, not a generic summary.
2. **Preserve learner effort.** Ask the learner to retrieve, predict, explain, or attempt before showing a complete answer when practical.
3. **Be transparent about evidence.** Label information as *From source*, *Inference*, or *Unknown / verify* when relevant.
4. **Respect constraints.** Time, deadlines, prerequisites, accessibility, and course rules matter. Ask only for missing details that change the answer materially.
5. **Create feedback loops.** Practice reveals a gap; feedback explains it; the next task tests whether the gap closed.
6. **Don't manufacture authority.** No grade guarantees, unsupported exam predictions, invented citations, or effectiveness claims without data.
7. **Install as skills, keep editing markdown.** A `.skill` file is a zip of a `SKILL.md` folder. The genuine artifact is the instructions, not the archive.
